Factory Inventory Management System

A full-stack demo: a Vue 3 single-page dashboard backed by a FastAPI service that serves in-memory data loaded from JSON files. There is no database.

Data flow

How a filter change on screen becomes a refreshed view.

  1. User changes a filter. FilterBar updates shared refs (period, location, category, status) in the useFilters singleton composable.
  2. View reacts. A view watching those refs calls getCurrentFilters(), which maps period to a month value and location to warehouse.
  3. API client builds the request. api.js drops any filter set to all and calls, for example, GET /api/orders?warehouse=...&status=....
  4. FastAPI filters in memory. The handler runs apply_filters (warehouse, category, status; case-insensitive) and filter_by_month (a month like 2025-09, or a quarter like Q3-2025) over the lists loaded at startup.
  5. Pydantic validates the response. Typed endpoints return a response_model; aggregate endpoints (dashboard, spending, reports) return computed dictionaries.
  6. Vue updates. Raw data lands in refs; derived values (totals, chart series) are computed properties, so the UI re-renders automatically.

Observations

Client and server are out of sync. api.js calls /api/tasks (GET, POST, PATCH, DELETE) and /api/purchase-orders (POST, GET by backlog item), and main.py defines a CreatePurchaseOrderRequest model, but no such routes exist in main.py. Those features will fail against the current backend.
  • Data is read once at startup; nothing persists across restarts.
  • CORS allows all origins and there is no authentication, which is fine for local demos only.
  • The API base URL is hard-coded to http://localhost:8001/api in api.js.
  • Quarter logic is duplicated: QUARTER_MAP and the if/elif chain in the quarterly report.
